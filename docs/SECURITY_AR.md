# الأمن والحدود (المرحلة J)

## الطبقات

| الطبقة | ما تفعله |
| --- | --- |
| مصادقة | JWT وصول قصير + رمز تجديد **يُدوَّر ويُستعمل مرة واحدة**، تجزئة scrypt |
| صلاحيات | RBAC في **طبقة الخدمة** — إخفاء أزرار الواجهة ليس حماية |
| حدّ معدل | نافذة منزلقة لكل عميل: مسارات المصادقة أشد (10/دقيقة افتراضًا) |
| حجم الطلب | 1 ميجابايت، باستثناء استيراد إصدار نص إداري |
| ترويسات | CSP مغلقة، `nosniff`، `DENY` للتأطير، `no-referrer`، HSTS في الإنتاج |
| سجل تدقيق | ملحق-فقط في ORM، ومحفّز Postgres يمنع UPDATE/DELETE في القاعدة |
| توثيق API | Swagger/ReDoc يُعطَّلان تلقائيًا في الإنتاج |

## جلسات التجديد

رمز التجديد **يُستعمل مرة واحدة**. تفصيله:

| السلوك | التنفيذ |
| --- | --- |
| ما يُخزَّن | معرّف الرمز (`jti`) لا الرمز — تسريب القاعدة لا يعطي رموزًا صالحة |
| التدوير | كل استعمال يُصدر خلفًا ويُبطل السابق في السلسلة نفسها |
| كشف السرقة | استعمال رمز مُبطل ⇐ تُبطل **السلسلة كلها** ويُسجَّل `reuse_detected` |
| إنهاء الجلسات | `POST /auth/sessions/revoke-all` وصفحة `/account` |
| رمز بلا جلسة | يُرفض بـ`SESSION_NOT_FOUND` ولو كان توقيعه صحيحًا |

> الاحتياط مقصود: قطع جلسة مستخدم صادق أهون من إبقاء جلسة سارق مفتوحة.

## قواعد لا تُخترق في الخدمة

- لا يعتمد أحد عمله: إصدار نص، ادعاء، قرار جذر، تصحيح — كلها تلزم طرفًا
  ثانيًا مستقلًا.
- لا يُكلَّف بالمراجعة من أقرّ بتضارب مصلحة في الكيان نفسه.
- المشروع الخاص لا يُقرأ إلا لأعضائه أو لأدوار الرقابة، والقائمة نفسها
  لا تسرّب عناوين ما لا يُقرأ.
- مسودة الادعاء خاصة بصاحبها والمراجعين، ولا تظهر في أي قائمة عامة.
- الاستيراد وإعادة الاشتقاق محفوظان لمسؤول النص والمدير التقني، ويُسجَّلان
  في سجل التدقيق بفاعل معروف.

## قاعدة البيانات في الإنتاج

يُنشأ دور تطبيق غير مميز لا يملك DDL ولا حذف سجل التدقيق:

```sql
CREATE ROLE quran_app LOGIN PASSWORD '...';
REVOKE ALL ON SCHEMA public FROM PUBLIC;
GRANT USAGE ON SCHEMA public TO quran_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO quran_app;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO quran_app;
-- سجل التدقيق: إضافة وقراءة فقط (والمحفّز يمنع الباقي دفاعًا ثانيًا)
REVOKE UPDATE, DELETE ON audit_logs FROM quran_app;
-- الهجرات تُشغَّل بدور مالك منفصل لا بدور التطبيق
```

`DATABASE_URL` في الإنتاج يشير إلى `quran_app`، وAlembic يُشغَّل بدور
المالك يدويًا عند النشر (`AUTO_CREATE_SCHEMA=false`).

## متغيرات البيئة الحساسة

| المتغير | ملاحظة |
| --- | --- |
| `JWT_SECRET` | **يجب** تغييره في الإنتاج؛ القيمة الافتراضية للتطوير فقط |
| `DATABASE_URL` | دور غير مميز |
| `ALLOWED_ORIGINS` | قائمة صريحة، لا `*` |
| `ENVIRONMENT` | `production` يفعّل HSTS ويعطّل التوثيق والحسابات التجريبية |
| `AI_FEATURES_ENABLED` | لا أثر له ما لم تجتز بوابة `GET /api/v1/ai/readiness` |

## ما لم يُنفَّذ بعد

- حدّ المعدل مشترك عبر عمليات متعددة (يلزم Redis عند النشر الأفقي).
- RLS في Postgres كطبقة ثالثة تحت RBAC.
- فحص أمني آلي في CI (SAST/تبعيات).
