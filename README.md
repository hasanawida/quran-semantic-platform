# منصة الاستقراء الدلالي لجذور ألفاظ القرآن الكريم

نسخة تأسيسية قابلة للتشغيل محليًا، مبنية على:

- Next.js للواجهة
- FastAPI للخلفية
- PostgreSQL للبيانات
- Redis للمهام والتخزين المؤقت
- Docker Compose للتطوير
- GitHub Actions للاختبارات

## تنبيه علمي

هذا المستودع لا يحتوي نصًا قرآنيًا كاملًا ولا تفاسير أو معاجم منسوخة.  
يجب إدخال النص والمصادر من نسخ موثقة ومرخصة، ثم مراجعتها وفق السياسة العلمية للمشروع.

لا يولّد النظام النص القرآني، ولا يعيد بناء الآية من جدول الكلمات، ولا يسمح بنشر التحليلات الآلية بوصفها نتائج معتمدة.

## التشغيل السريع

1. انسخ ملف البيئة:

```bash
cp .env.example .env
```

2. شغّل الحاويات:

```bash
docker compose up --build
```

3. افتح:

- الواجهة: http://localhost:3000
- API: http://localhost:8000
- Swagger: http://localhost:8000/docs

## اختبار النظام

```bash
docker compose exec api pytest
```

## التشغيل بدون Docker

إن لم يتوفر Docker على جهازك:

1. ثبّت PostgreSQL 16 وRedis محليًا (أو استخدم خدمة سحابية للتطوير)، وطبّق `apps/api/sql/001_init.sql`.
2. شغّل الخلفية:

```bash
cd apps/api
python -m venv .venv
.venv/Scripts/pip install -e ".[dev]"
.venv/Scripts/python -m uvicorn app.main:app --reload --port 8000
```

3. شغّل الواجهة:

```bash
cd apps/web
npm ci
npm run dev
```

ملاحظة: اختبارات الوحدات الحالية لا تحتاج قاعدة بيانات: `pytest` داخل `apps/api` يكفي.

قاعدة التطوير SQLite تُنشأ وتُبذر تلقائيًا في `apps/api/data/app.db` عند أول
إقلاع. حذف الملف يعيد البذر من الحزمة.

### حسابات التطوير

تُنشأ تلقائيًا خارج بيئة الإنتاج لتجربة سير المراجعة المزدوجة فورًا
(كلمة المرور للجميع `demopass123`):

| البريد | الأدوار |
| --- | --- |
| `admin@qsp.example` | مدير تقني + مسؤول النص |
| `reviewer1@qsp.example` | مدير الجودة |
| `reviewer2@qsp.example` | مراجع لغوي |
| `sharia@qsp.example` | مراجع شرعي |

النطاق `.example` محجوز قياسيًا (RFC 2606). لا تستعمل نطاقًا بلا نقطة
(`@local`) ولا نطاقًا خاصًا (`.test`, `.local`, `.localhost`, `.invalid`):
مدقق البريد يرفضها فتصير الحسابات غير قابلة لتسجيل الدخول.

## البيانات القرآنية (البحث بالجذر عن الآيات)

النص والجذور **لا يكتبان يدويًا**؛ يبنيان من مصادر خارجية موثقة:

- **نص المصحف** (رواية حفص، الرسم العثماني): مشروع تنزيل <https://tanzil.net>
- **الجذور والصرف**: المدونة القرآنية بجامعة ليدز <https://corpus.quran.com>
  (رخصة GNU — يلزم ذكر المصدر ورابطه وعدم تعديل الملف)

## الرخصة

**الشيفرة** تحت [AGPL-3.0](LICENSE): من شغّل نسخة معدَّلة خدمةً على
الشبكة لزمه إتاحة شيفرته لمستعمليها. اختيرت لأن منطق المنصة العلمي —
كيف تُنسب الجذور وكيف يُعرض الخلاف — يجب أن يبقى مكشوفًا لمن يعتمد عليه.

**البيانات المستوردة رخصها مستقلة ولا تشملها AGPL.** وأهمّ قيد فيها:
شرط ليدز **غير التجاري**. فتشغيل المنصة تجاريًا يحتاج إذنًا مستقلًا من
جامعة ليدز أو استبدال المصدر الصرفي. التفصيل الكامل — وما لا يجوز
اقتطاعه عند إعادة النشر — في [NOTICE](NOTICE).

الملفات المصدرية في `data/raw/`، وسكربت البناء يتحقق بنيويًا (114 سورة،
6236 آية، تسلسل صحيح، تطابق المصدرين) ثم ينتج حزمة موثقة ببصمات:

```bash
python scripts/import-quran/build_bundle.py
```

الحزمة الناتجة `apps/api/data/quran_bundle.json.gz` (~470 كيلوبايت) تُبذر في
قاعدة البيانات عند أول إقلاع. البيانات حالتها «مستورد — غير معتمد» وتظهر
كذلك في الواجهة، ولا تعد نتائج معتمدة حتى تجتاز مراجعة المنصة.

**فصل البسملة:** ملف تنزيل المستعمل يدمج البسملة داخل الآية الأولى من كل
سورة عدا الفاتحة وبراءة. يفصلها السكربت نقلًا حرفيًا ويحفظها بيانًا للسورة،
وإلا عُرضت «2:1» مخالفة للعد الكوفي وانزاح ترقيم الكلمات أربعًا. تفصيله في
`docs/PHASE_D_MORPHOLOGY_AR.md`.

مسارات البحث بالجذر:

```text
GET /api/v1/roots/{الجذر}                 معلومات الجذر وعدد المواضع
GET /api/v1/roots/{الجذر}/occurrences     الآيات مع تمييز الكلمات المشتقة
```

### التحليل الصرفي (المرحلة D)

حزمة ثانية تحمل التحليل الصرفي الكامل (128,219 مقطعًا) بصيغها ووسومها
وسماتها حرفيًا كما في المصدر:

```bash
python scripts/import-quran/build_morphology_bundle.py
cd apps/api && .venv/Scripts/python.exe -m app.cli bootstrap
```

`bootstrap` ينشئ المخطط ويبذر النص ثم يشغّل خط الصرف كاملًا: ترميز الكلمات
← استيراد التحليل ← اشتقاق مواضع الجذور ← فحص المواضع المرجعية (~80 ثانية).

```text
GET /api/v1/morphology/ayahs/{سورة}/{آية}   تحليل كل كلمة مفصولًا بمصدره
GET /api/v1/surahs/{سورة}/ayahs             السورة كاملة، والبسملة بيانًا لها
GET /api/v1/morphology/search              بحث بأبعاد الصرف (زمن، وزن، بناء، إعراب)
GET /api/v1/morphology/dimensions          الأبعاد وقيمها بتسمياتها العربية
GET /api/v1/roots/compare?roots=سأل,قول    مقارنة توزيع الجذور والآيات المشتركة
GET /api/v1/methodology                    المصادر والمنهج ومواضع الخلاف
```

صفحات التصفح: `/mushaf/[surah]` للسورة كاملة، و`/root/[root]` صفحة ثابتة
لكل جذر تعمل بلا JavaScript، و`/morphology` للبحث بالصيغة الصرفية، و`/compare` لمقارنة الجذور، و`/methodology` لبيان المنهج والمصادر ومواضع الخلاف.

## محتوى النسخة الحالية

- Health API
- بيانات السور الأساسية
- نموذج إصدارات النص
- نموذج الآيات
- API لعرض الآية المنشورة
- نموذج الجذور
- API بحث أولي بالجذر
- تطبيع عربي للبحث فقط (سياسة همزات موثقة: الجذر المهموز مفتاح واحد قانوني ء)
- عقد استجابة موحد success/data/meta مع request_id ومعالجات أخطاء موحدة
- Migration أولية مع فهرس بحث نصي وحماية سجل التدقيق من التعديل والحذف
- واجهة عربية RTL بنظام تصميم رمزي وخطوط عربية (Amiri للقرآني، Noto للنص والواجهة)
- تطبيق هاتف قابل للتثبيت (PWA) بعمل بلا اتصال وشارة صريحة له
- مصادقة JWT بتدوير رموز التجديد وكشف إعادة الاستعمال، سبعة أدوار، RBAC في طبقة الخدمة
- آلة حالة إصدارات النص: استيراد ← تحقق ← اعتماد مزدوج ← تفعيل ذري
- خط الصرف متعدد المصادر: ترميز موثق، استيراد منسوب، كشف تعارض، قرارات
  مراجعة بمنع الاعتماد الذاتي، اشتقاق حتمي لمواضع الجذور
- مصادر علمية واستشهادات وادعاءات: لا ادعاء بلا دليل من مصدر متحقَّق منه
- مشاريع خاصة وتقارير ذات نسخ مبصومة غير قابلة للتعديل
- صندوق مراجعة: تكليفات، تضارب مصالح، خلافات ظاهرة، تصحيحات قبل/بعد
- تصدير ببيان أصول كامل (JSON / CSV / Markdown) وبصمة لكل مخرَج
- حدود معدل وترويسات أمان وحدّ حجم الطلب ومحفّز حماية سجل التدقيق
- بوابة ذكاء اصطناعي تمنع تشغيله قبل اكتمال سلامة البيانات والمراجعة
- 126 اختبارًا (وحدات وعقد وتكامل وأمن وسلامة نص ومنهج)
- Docker وCI (فحص، هجرات ذهابًا وإيابًا، اختبارات، بناء الواجهة)
- وثائق السلامة العلمية

## غير متضمن بعد

- نسخ احتياطي ومراقبة تشغيلية وإصدار تجريبي مغلق (المرحلة 5 جزئيًا)
- RLS في Postgres، وحدّ معدل مشترك عبر العمليات
- أي ميزة ذكاء اصطناعي فعلية — البوابة فقط، والشروط لم تكتمل

هذه العناصر موضوعة في `docs/IMPLEMENTATION_ROADMAP.md`.

## التصميم

نظام واحد في `apps/web/app/globals.css`: رموز أولًا (لا قيمة خام في
مكوّن)، أساسيات مشتركة (سطح، رقاقة، زر، جدول) تُعرَّف مرة وتُستعمل في كل
صفحة، وRTL أصيل بخصائص منطقية. وضع داكن كامل بإعادة تعريف الرموز نفسها،
وتباين يجتاز WCAG AA في الوضعين، وأهداف لمس لا تقل عن 44px على الهاتف.

## تطبيق الهاتف

الموقع نفسه تطبيق قابل للتثبيت (PWA): أيقونات مولَّدة، اختصارات، وعمل
بلا اتصال لما سبقت زيارته — مع شارة صريحة تنبّه أن المعروض قد لا يكون
أحدث ما على الخادم. لا تُخزَّن استجابات المصادقة ولا المسارات الإدارية
إطلاقًا. التفاصيل وخطوات التثبيت في `docs/DEPLOYMENT_AR.md`.

```bash
python scripts/build-icons.py   # توليد أيقونات PNG بلا تبعيات
```
